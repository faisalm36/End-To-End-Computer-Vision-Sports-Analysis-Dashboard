## Overview

This release improves speed calculation to use **sustained speeds** and **realistic thresholds** based on GPS standards. The previous 22 mph filter was too low and would have dropped real elite sprints (fastest PL 2025/26: 37.3 km/h = 23.2 mph).

---

## Changes Summary

### 1. ✅ Raised Outlier Filter Threshold

**Problem**: 22 mph filter would drop elite sprints

**Fix**:
- `max_plausible_speed_mph`: 22.0 → **25.0 mph** (~40 km/h)
- Only filters **extreme outliers**, not real sprints
- Fastest recorded PL speed (2025/26): 37.3 km/h = 23.2 mph ✅ now passes

**Usage**: Filter value is configurable, used only to drop outlier steps (never clamps)

---

### 2. ✅ Sustained Speed Calculation

**Problem**: Single-frame spikes set top speed

**Fix**: Implemented sustained speed requirement (~1 second)

**New Method**: `calculate_sustained_speeds(speeds) -> List[float]`
- Rolling window median over ~1 second (30 frames at 30 FPS)
- Filters single-frame detection errors
- Preserves real sprint bursts
- Top speed = 99th percentile of sustained speeds (not instantaneous max)

**Example**:
```python
# Instantaneous speeds: [10, 10, 10, 30, 10, 10, 10]  # spike!
# Sustained speeds:     [10, 10, 10, 10, 10, 10, 10]  # filtered
```

---

### 3. ✅ GPS Standard Thresholds (Default Preset)

**Previous** (arbitrary):
- HSR: 15.0 mph
- Sprint: 18.0 mph

**New** (GPS standard):
- **HSR**: 19.8 km/h = **12.3 mph**
- **Sprint**: 25.2 km/h = **15.7 mph**

**Presets Supported** (documented, not all implemented):
1. `gps_standard` (default): 19.8 / 25.2 km/h
2. `gps_round`: 20 / 25 km/h
3. `percent_max`: 60% / 80% of personal max (future)

---

### 4. ✅ Sprint Detection with Hysteresis

**Problem**: Rapid on/off toggling at threshold boundary

**Fix**: Hysteresis implementation
- **Enter sprint**: Speed ≥ threshold (15.7 mph)
- **Exit sprint**: Speed < 90% of threshold (14.1 mph)
- Prevents rapid toggling
- More accurate burst counting

**Example**:
```
Speed:   [10, 15, 16, 17, 15, 14.5, 14, 13, 10]
Before:  [_, _, S, S, S, _, _, _, _]  # 1 burst
After:   [_, _, S, S, S, S, S, _, _]  # 1 burst, stays in sprint longer
```

---

### 5. ✅ Configurable Dwell Time

**New Config**:
- `SUSTAINED_SPEED_WINDOW_S = 1.0` (seconds)
- Requires speed to be sustained for ≥1 second
- Applied to both top speed and HSR/sprint thresholds

## Implementation Details

### Sustained Speed Calculation

```python
def calculate_sustained_speeds(self, speeds: List[float]) -> List[float]:
    """Calculate sustained speeds using rolling window median.
    
    Requires speed to be sustained for ~1 second (rolling window).
    This filters single-frame spikes while keeping real sprints.
    """
    sustained = []
    half_window = self.sustained_speed_window_frames // 2
    
    for i in range(len(speeds)):
        start = max(0, i - half_window)
        end = min(len(speeds), i + half_window + 1)
        window = speeds[start:end]
        
        # Use median for robustness
        sustained.append(np.median(window))
    
    return sustained
```

### Top Speed Calculation

```python
# Filter extreme outliers
valid_speeds = [s for s in speeds if s <= max_plausible_speed_mph]

# Calculate sustained speeds
sustained_speeds = calculate_sustained_speeds(valid_speeds)

# 99th percentile for robust top speed
sorted_sustained = sorted(sustained_speeds, reverse=True)
percentile_idx = int(len(sorted_sustained) * 0.01)
robust_max_speed = sorted_sustained[percentile_idx]
```

### Sprint Detection with Hysteresis

```python
sprint_count = 0
in_sprint = False
sprint_exit_threshold = sprint_threshold_mph * 0.9  # 90%

for speed in sustained_speeds:
    if not in_sprint and speed >= sprint_threshold_mph:
        sprint_count += 1
        in_sprint = True
    elif in_sprint and speed < sprint_exit_threshold:
        in_sprint = False
```

## Known Limitations

### Sustained Speed Window
- May slightly underestimate true top speed if burst < 1 second
- Trade-off: accuracy vs spike filtering (we prioritize accuracy)

### GPS Thresholds
- Standard for GPS devices, may differ from broadcast tracking
- Configurable if different standards needed

### Preset Support
- Only `gps_standard` fully implemented
- `gps_round` and `percent_max` documented but not active
- Easy to add: just set config values
