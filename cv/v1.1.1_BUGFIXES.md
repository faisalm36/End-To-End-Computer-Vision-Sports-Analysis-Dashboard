## Bugs Fixed

### 1. ✅ Calibration Logging Inconsistency

**Problem**:
- Logs said "Using default calibration" AND "No calibration provided - pitch coordinates will not be computed"
- Yet pitch coordinates were computed
- Warnings array in meta.json stayed empty `[]`

**Root Cause**:
- Config printed "Using default calibration" warning
- run_pipeline.py printed "No calibration provided" when `--calibration` omitted
- pipeline.py only added warning to meta.json if `homography` was None (but it was created with default)

**Fix**:
- Config stores warning in `calibration_warning` attribute
- Removed duplicate warning from run_pipeline.py
- Pipeline adds config warning to meta.json warnings array
- Logging now consistent: one clear message about default calibration

**Files Changed**:
- `cv/config.py`: Added `calibration_warning` attribute

### 2. ✅ Team Classifier Short Clip Support & Role Consistency

**Problem**:
- Team classifier only fit at frame 300
- Shorter clips (3s = 90 frames, 12s = 360 frames) got `team: null` for all
- Role inconsistent: `'unknown'` in player_match_stats but `'player'` in tracking_detections
- `'unknown'` not documented as valid value

**Root Cause**:
- `fit_teams()` checked `frame_count < early_frames_count` and returned early
- `get_role()` returned `'unknown'` for tracks not in dictionary
- No fallback fitting at end of video

**Fix**:
- Team classifier now fits at `min(early_frames_count, total_frames-1)`
- If still not fitted at end, force fit with `frame_count = processed_frames`
- Added `min_samples` guard (4 tracks minimum) with clear warning
- Lower `min_observations` for voting (3-5 instead of 10) for short clips
- `get_role()` returns `'player'` for unknown tracks (never `'unknown'`)
- Pipeline ensures role is never `'unknown'` in outputs

**Allowed Roles** (documented):
- `player`: Default for all non-referee players
- `referee`: Color outlier detected by clustering
- `ball`: Special role for ball track (-1)
- ~~`goalkeeper`~~: **Not supported** (detection not implemented)

**Files Changed**:
- `cv/pipeline.py`: Fit at min(300, end) + force fit at end if needed
- `cv/team_classifier.py`: `fit_teams(min_samples=4)`, `get_role()` defaults to `'player'`

### 3. ✅ Speed Calculation - Cap Before Max Bug

**Problem**:
- Every track hit 22.0 mph max in both runs (synthetic 12s and 3s)
- Capping implausible speeds BEFORE taking max meant all reported 22.0
- Single-frame spikes (detection errors) set top speed

**Root Cause**:
```python
# OLD CODE
speed_mph = min(speed_mph, self.max_plausible_speed_mph)  # Cap at 22 mph
speeds.append(speed_mph)
# ...
return {'max_speed_mph': max(speeds)}  # Always 22 if any outliers!
```

**Fix**:
- Removed pre-capping in `calculate_speed()` - preserve raw speeds
- `calculate_workload_metrics()` filters outliers: `valid_speeds = [s for s in speeds if s <= 22]`
- Use **95th percentile** of valid speeds for robust top speed (not max)
- Filters single-frame spikes while keeping real bursts

**New Logic**:
```python
# Filter outliers
valid_speeds = [s for s in speeds if s <= max_plausible_speed_mph]

# 95th percentile for robust max
sorted_speeds = sorted(valid_speeds, reverse=True)
percentile_idx = int(len(sorted_speeds) * 0.05)  # Top 5%
robust_max_speed = sorted_speeds[percentile_idx]
```

**Tests Added**:
1. `test_speed_capping`: Implausible speed (100m in 1s) filtered, not capped
2. `test_real_top_speed_below_cap`: Real 19 mph reported correctly (not 22)
3. `test_single_frame_spike_filtered`: Spike filtered by 95th percentile

**Files Changed**:
- `cv/metrics.py`: Removed pre-cap, added outlier filtering + 95th percentile
- `cv/tests/test_metrics.py`: Added 3 new speed tests

### 5. ✅ Meta.json & EasyOCR Warning

**Problem**:
- Torch `quantize_per_tensor` deprecation warning in logs
- Meta.json missing `width`/`height` as integers

**Root Cause**:
- EasyOCR uses torch quantization on all devices
- Quantization deprecation warning on mps/cpu
- Meta.json only had `resolution` string

**Fix**:
- Pass `quantize=False` on mps/cpu (only quantize on CUDA for performance)
- Added warning filter: `warnings.filterwarnings('ignore', category=UserWarning, message='.*quantize_per_tensor.*')`
- Added `width` and `height` as ints to meta.json (kept `resolution` for compatibility)

**meta.json Schema Update**:
```json
{
  "resolution": "1920x1080",  // kept for compatibility
  "width": 1920,              // NEW ✨
  "height": 1080              // NEW ✨
}
```

**Files Changed**:
- `cv/ocr.py`: Added quantize=False + warning filter
- `cv/pipeline.py`: Added width/height to meta.json

## Known Limitations

### Team Classification
- Requires ≥4 tracks to fit (2+ per team)
- Very short clips (<3s, <90 frames) may have insufficient data
- Low color contrast (e.g., white vs light blue) may confuse teams

### Speed Calculation
- 95th percentile may underestimate true top speed if only few high-speed bursts
- For most use cases, provides more accurate result than max (which is noise-prone)

### Goalkeeper Detection
- **Not implemented**
- All players labeled as `'player'`
- Future: heuristic (color outlier + position near goal)
